## Deviations / decisions the senior should know (please confirm or override)

- **D-1 — «چطور کار می‌کند؟» is a non-navigating `<button>`**, exactly like the wireframe (`<div class="link">`).
  The order said "ghost link"; ghost *styling* + wireframe *behavior* can't both hold. I kept it keyboard-focusable
  and 44 px tall. Please pick the target (Q-08) and I'll wire it in T-003B or a follow-up.
- **D-2 — `skipTrailingSlashRedirect: true` added in `next.config.ts` (NEW config knob).** D-S6 says every
  `/api/*` call carries its trailing slash. Next's default is a **308 that strips the slash** (`/api/me/` → `/api/me`),
  which would change the path on our own API calls. In the compose stack Caddy routes `/api/*` to Django first, so
  prod is unaffected either way; the flag makes `next dev` and a bare-standalone preview behave exactly like prod.
  Evidence: before the flag, `curl -i localhost:3100/api/me/` returned
  `308 … location: /api/me`; after it, the browser request stays `GET http://localhost:3100/api/me/`.
  It is a frontend-local config change (no infra file touched) — but it is a new knob, so it is flagged, not smuggled.
- **D-3 — no `meta theme-color`.** A theme-colored browser bar needs literal hexes in `layout.tsx`, which §3 and
  "no hard-coded colors" forbid. Dropped it and used `color-scheme` in CSS instead.
- **D-4 — `styles/tokens.css` + `check:tokens` need the repo checkout.** `docker/Dockerfile.frontend` builds with
  context `./frontend`, so `../design/brand-kit/palette.md` is not in the build context. Consequence: the token
  diff gate is a **lane** gate (`npm run check:tokens` from a checkout), not part of `npm run build`, and the image
  build never reads the palette. If you'd rather have it inside the image build, the palette needs a copy under
  `frontend/` (or the build context must change) — your call, escalated in the report rather than guessed.
- **D-5 — ESLint 9, not 10.** `eslint-config-next@16.3.6` declares peer `eslint >=9.0.0`, but its bundled
  `eslint-plugin-react` crashes on ESLint 10 (`TypeError: contextOrFilename.getFilename is not a function`).
  Pinned `eslint 9.39.5` (latest 9.x) and verified green. Will revisit when the plugin supports 10.
- **D-6 — contrast flag (design, not code).** With the palette exactly as given: light `--soft #6E7989` on `--bg`
  `#F5F2EA` = **3.94:1** and on `--card` `#FDFCF8` = 4.30:1; dark `--primary #6E8CA8` on `--primary-bg` = 3.82:1.
  `tests.md` §D asks ≥4.5:1 for body text, so soft/secondary text sizes must stay "large" (or the palette gets a
  nudge). I changed nothing — the palette is the source of truth — flagging it for a design decision.
  All other pairs pass: light text/bg 11.10, on-primary/primary 6.31, primary/bg 6.31, primary/primary-bg 5.78;
  dark text/bg 13.85, soft/bg 6.80, on-primary/primary 4.67, primary/bg 4.93.
- **D-7 — screenshots needed a fallback browser.** Playwright's browser CDN and `apt` are unreachable in this
  sandbox, so `npx playwright install chromium` fails. I rendered the screenshots with a Chromium 153 binary that
  ships as an npm package (`@sparticuz/chromium`, installed **outside the repo** in `/tmp`, not a project
  dependency). Relevant for **T-024**: the Playwright smoke run will need either Chromium download access in CI,
  or the same npm-shipped-browser fallback. `frontend/` itself is unaffected.
- **D-8 — `npm start` prints a warning** ("`next start` does not work with `output: standalone`"). `next dev` and
  the standalone server both work; T-004 should keep `npm run start` out of any gate.
